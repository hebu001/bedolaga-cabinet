# Сохранение кастома EvoVPN при переносе upstream 1.79.0

Дата: 2026-09-28. Статус: кастом перенесён в локальный frontend-кандидат и проверен на исходниках, автоматических тестах и синтетических экранах. Target-bot schemas и live E2E остаются отдельным этапом. Pixel-identical результат и работа новой связки в проде не заявляются.

Baseline — установленный fork `55a4038f4ae8692922abc2622f97309840f71064` (1.57.1); upstream — tag `v1.79.0`, `f5ea595f8f732c37f2d5c270f34879ab2e2fba2d`. Этот реестр сохраняет сценарии, а не старую структуру каждого компонента: новая декомпозиция upstream принята там, где поведение перенесено и проверено. `docs/design-options/*` не использовался как разрешение заменить кастомный дизайн.

Точные migration maps старых и новых тестов: [USER-MERGE](USER-MERGE.md) и [ADMIN-MERGE](ADMIN-MERGE.md). Все 11 custom suites остаются в `npm test` вместе с upstream Vitest. Некоторые прежние declaration-extraction cases теперь исполняют настоящие новые компоненты в Vitest; это объясняет изменение числа custom cases, а не потерю сценариев.

## Визуальные свидетельства и пределы

Выполнены 54 viewport captures при 390×844 и 1440×900: 24 baseline + 30 candidate. Из них 42 пользовательских кадра и 12 админских: список пользователей, обзор карточки пользователя и её диалог тикета. Одинаковые synthetic fixtures покрывают login, dashboard, subscription, balance, profile, support list/detail, tariff purchase и выбранный 90-дневный период. Candidate дополнительно показывает inline shortage top-up, выбор второй подписки и раскрытые уведомления. Оранжевые/белые акценты, evo logo, dark surfaces, dock/sidebar и основные правила прокрутки проверены по PNG. В итоговых прогонах: 0 page errors, 0 неожиданных fixture API requests, 0 горизонтальных переполнений.

Покупка намеренно имеет новую структуру upstream, Dashboard получил выбор подписки и локализованные числа. Pixel-identical сравнение не было целью. Нативный Telegram WebView, клавиатура/touch, live fonts/branding, все локали и все состояния ошибок этим Chromium-прогоном не доказаны. Список пользователей, обзор карточки и её диалог тикета сравнены на mobile/desktop: исправлены синие avatars, navy secondary surfaces, чрезмерная непрозрачность hairlines и обрезание имени/email в mobile header. Итоговые PNG показывают orange avatars, gray surfaces, тонкие 8% hairlines и читаемый header с actions на отдельной строке. Полный admin tariffs/Remnawave visual baseline пока отсутствует.

Снимки, harness и JSON-метрики — локальный артефакт вне этого Git-репозитория: `work/cabinet-visual-20260928/README.md` и `evidence/` общей рабочей папки. [Локальная ссылка](../../../cabinet-visual-20260928/README.md) работает лишь при наличии соседнего каталога. В обычном clone используйте краткие результаты этого документа или запросите артефакт. Внешние HTTP/WS в harness заблокированы; реальные аккаунты, токены, платежи и серверные данные не использовались.

Итоговые общие проверки и ограничения — [FRONTEND-HANDOFF](FRONTEND-HANDOFF.md). Возможности нового backend включаются только по [CONTRACT](CONTRACT.md); все 14 integration flags пока false. Серверы и прод не менялись.
